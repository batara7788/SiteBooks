# Мастер-промпт: сайт с книгами на gnida.world

> Этот файл — CLAUDE.md, подхватывается автоматически в начале каждой сессии.

---

## 1. Что это за проект

Личный сайт для чтения книг. Я пишу книги, и хочу, чтобы люди читали их
прямо в браузере — не скачивая Word или PDF.

**Это не коммерческий проект.** Никакой рекламы, аналитики слежения,
поп-апов «подпишитесь», сбора почт, пейволлов. Пришёл, открыл, читает.
Если предлагаешь фичу, которая тянет за собой монетизацию или сбор
данных — не предлагай.

Главная ценность — текст и удобство чтения. Всё остальное подчинено этому.

## 2. Инфраструктура

| Что | Где |
|---|---|
| Домен | `gnida.world` |
| DNS | Cloudflare (аккаунт уже есть, домен уже там) |
| Хостинг | Cloudflare Pages, статика |
| Репозиторий | GitHub |
| Сервер | **нет и не нужен** |

**Почему без сервера.** Закладка, тема, размер шрифта хранятся в
`localStorage` браузера читателя. Синхронизация между устройствами не
нужна. Раз состояния на сервере нет — нечему падать, нечего платить,
ничто не засыпает.

**Важно про текущее состояние домена.** На `gnida.world` сейчас висит
Cloudflare Worker (`tight-resonance-56e0`), который отдаёт страницу с
гифкой. Пока его маршрут не снят, он перехватывает запросы и сайт не
покажется. Убирается в Cloudflare → Workers Routes → удалить маршрут на
`gnida.world`.

**Отдельно:** на поддомене `sudroch.gnida.world` живёт другой мой проект
(мультиплеерное судоку на Render). Его не трогать, он к книгам отношения
не имеет.

## 3. Структура репозитория

```
site/
  index.html              полка с книгами
  read.html               читалка
  assets/
    style.css             все стили, светлая и тёмная тема
    shelf.js               логика полки
    reader.js               логика читалки
  data/
    <id-книги>/
      meta.json           оглавление, статистика
      <часть>.json        текст части
      media/              иллюстрации
build/
  parse_docx.py           конвертер Word → JSON
```

Настройки Cloudflare Pages: build command пустой, output directory `site`.

## 4. Как книга попадает на сайт

Я пишу в Word. Оттуда текст вынимается один раз скриптом и кладётся
рядом в виде JSON. Word — только источник, на сайте его нет.

```bash
python3 build/parse_docx.py книга.docx site/data ID "Название" "Подзаголовок"
```

Потом ID дописывается в массив `BOOKS` в `site/assets/shelf.js`.

### Что конвертер понимает

| В Word | На сайте |
|---|---|
| Заголовок 1 | часть |
| Заголовок 2 | глава, отдельная страница |
| Заголовок 3 | подраздел внутри главы |
| Заливка фона абзаца | врезка со своим цветом и подписью |
| Жирный, курсив, зачёркнутый | как есть |
| Таблицы | таблица, прокручивается вбок на телефоне |
| Картинки | выносятся в `media/`, вставляются по месту |
| Списки | маркированный список |
| Сноски | нумерованные, со ссылкой обратно |

### Подводные камни, уже наступленные

**В файле «Философия» стили заголовков продублированы.** Из-за этого
pandoc и другие готовые конвертеры теряют всю иерархию и выдают книгу
сплошным текстом без единого заголовка. Поэтому `parse_docx.py` читает
`word/document.xml` напрямую. Не переписывай его на pandoc — сломается.

**Врезки распознаются по цвету заливки.** Соответствие цвет → тип задано
словарём `FILL_KINDS` в начале скрипта. Если в новой книге появятся
другие цвета, их надо дописать туда, иначе врезка станет обычным серым
блоком. После конвертации новой книги — всегда проверяй, сколько врезок
каждого типа получилось, и сверяй с оригиналом.

## 5. Врезки — самое ценное в книгах

В «Философии» их 309 штук, двенадцать типов. Это не украшение, это
каркас: они разбивают длинный текст и дают читателю опоры.

Типы: В ДВУХ СЛОВАХ · ГЛАВНОЕ ИЗ ГЛАВЫ · ЭТО ИНТЕРЕСНО · СЛОВО В
ОРИГИНАЛЕ · РАСПРОСТРАНЁННОЕ ЗАБЛУЖДЕНИЕ · СПОРНЫЙ ВОПРОС · МЫСЛЕННЫЙ
ЭКСПЕРИМЕНТ · ФОРМУЛА · ЦИТАТА · А КАК К ЭТОМУ ПРИШЛИ? · МИНИ-ТАЙМЛАЙН ·
ЖИЗНЬ ФИЛОСОФА

**Как они устроены на сайте и почему именно так.** Цветная полоса слева
плюс подпись капсом. Фон почти прозрачный — потому что двенадцать
сплошных заливок подряд превращают главу в лоскутное одеяло. Цвета взяты
не из Word, а пересобраны в одну приглушённую гамму. В тёмной теме свои
осветлённые оттенки: пастель из Word на чёрном выглядит грязью.

Цитаты идут курсивом, формулы — моноширинным.

Если будешь трогать врезки — сохраняй этот принцип: цвет несёт полоса,
не заливка.

## 6. Дизайн и типографика

### Главное правило

Человек читает семь часов подряд. Всё подчинено тому, чтобы через час
не уставали глаза.

- Фон не белый, а тёплый (`#faf7f0`). Чистый белый на длинном тексте бьёт.
- Строка ограничена по ширине (~36rem). Длинная строка — глаз теряет начало следующей.
- Текст тёмный и плотный. Тонкие штрихи выглядят бледно, особенно в кириллице.

### Что уже решено и проверено

**Шрифт.** Первый заход был на Literata — я забраковал, слишком тонкие
буквы, «как в Word». Сейчас читатель выбирает сам из трёх:

- `serif` — PT Serif, классический книжный
- `slab` — Roboto Slab, **по умолчанию**: засечки есть, но штрих ровный и плотный
- `sans` — Inter, без засечек, максимально чёткий

**Тёмная тема добавляет вес шрифту автоматически.** Светлый текст на
тёмном всегда кажется тоньше, чем он есть — если не компенсировать,
тёмная тема выглядит бледной даже с правильным шрифтом.

**Цвет как акцент, а не фон.** Синь с золотом, которые я люблю и которые
мы делали для судоку, для чтения книги не годятся. Здесь спокойный фон и
скупой цвет: только врезки и ссылки.

### Чего не делать

- Не добавляй анимации появления текста при прокрутке.
- Не делай «прогресс чтения» навязчивым — тонкой полоски сверху достаточно.
- Не ставь шрифты с тонким начертанием в основной текст.
- Не делай колонку шире — соблазн заполнить широкий экран есть, но читать станет хуже.

## 7. Что умеет читалка

- Оглавление: части → главы, выезжает сбоку
- Два режима чтения, переключаются: **по главам** (короткие страницы) и **часть целиком** (одна лента)
- Закладка: запоминает главу, на полке появляется «продолжить»
- Настройки: тема, шрифт, четыре размера, три межстрочных интервала
- Навигация «назад / дальше» внизу главы
- Всё запоминается в браузере

ошибка. Добавление книги должно оставаться двумя действиями: запустить
скрипт, дописать ID в список.

## 9. Как со мной работать

Это важнее технических деталей выше.

1. **Не додумывай за меня.** Ты не читаешь мои мысли. Если в задаче
   пробел — спроси, а не выбирай молча за меня.

2. **Спрашивай точечно, как старший архитектор.** По одному вопросу или
   маленькими группами, чтобы я мог разобраться. Не вываливай десять
   вопросов сразу.

3. **Прямо говори о противоречиях.** Если я прошу одно, а раньше просил
   другое — скажи об этом, не выполняй молча последнее.

4. **Не выдавай свои допущения за мои требования.** Если пришлось что-то
   предположить — назови это вслух.

5. **Перед работой перескажи задачу своими словами** и дождись моего
   «да». Если задача простая и однозначная — не тяни, уточни только
   существенное.

6. **Проверяй то, что сделал, а не описывай.** Запусти, открой в
   браузере, посмотри. Если что-то нельзя проверить в твоём окружении —
   скажи об этом честно, а не показывай мне результат, выдавая за
   проверенный.

7. **Комментарии в коде — по делу.** Объясняй, *почему* так сделано,
   особенно неочевидные решения. Не пересказывай построчно, что и так
   видно из кода.

8. **Языки.** Со мной по-русски. Интерфейс сайта по-русски. Код и
   названия файлов — латиницей.
